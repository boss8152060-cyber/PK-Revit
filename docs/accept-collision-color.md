## A. Rebar Collision
### ทำอะไร
1. ขอบเขต: เหล็กของ host ที่เลือก (เลือกไว้ก่อน หรือปุ่ม "เลือก host" ทีละตัว/ตาม Mark) · เหล็กที่เห็นใน view · ทั้งโมเดล — ครอบ Rebar / FabricSheet / RebarInSystem (Area/Path)
2. **ขั้น 1**: bounding box overlap + ระยะ clearance (sweep-and-prune แกน X) ข้ามคู่ที่ host เดียวกัน; RebarInSystem ใน view/โมเดลหา host ไม่ได้ (ช้ามาก) จึงเทียบกับทุกตัว ไม่ข้าม
3. **ขั้น 2** เฉพาะคู่ที่ผ่านขั้น 1 เรียงจากซ้อนลึกสุดก่อน จำกัดจำนวน (ตั้งต้น 2,000 คู่) มีตัวนับความคืบหน้าและปุ่มยกเลิก:
   - Rebar↔Rebar: ระยะเส้นศูนย์กลางทุกตำแหน่งในชุด (`GetCenterlineCurves`) ลบรัศมี `BarModelDiameter/2` ของทั้งสอง → gap ≤ 0 = **ชน**, 0 < gap < ระยะห่างขั้นต่ำ = **ใกล้เกิน**, นับ "จำนวนจุดชน" ในชุด
   - FabricSheet/RebarInSystem หรืออ่านเส้นศูนย์กลางไม่ได้: solid intersection จริง (`BooleanOperationsUtils`, ปริมาตร > 1e-9 ft³) — ไม่ตรวจ clearance ของคู่ประเภทนี้
   - ตรวจละเอียดไม่ได้เลย → รายงาน "bbox ซ้อน (ยังไม่ยืนยัน)" ไม่ทิ้ง
4. รายงานเป็นต้นไม้: กลุ่ม = คู่ host (จำนวนจุดรวม/ชน/ใกล้เกิน) → คู่เหล็ก (สถานะ, gap มม., จำนวนจุด) **คลิกแถว = เลือก + ซูมใน view**
5. ส่งออก CSV UTF-8 BOM; log `%LOCALAPPDATA%\PKRevit\RebarCollision.txt`; ไม่แก้โมเดล (ไม่มี Transaction)

### ขั้นทดสอบและผลที่คาดหวัง
| # | ทำ | คาดหวัง |
|---|---|---|
| 1 | โมเดลไม่มีเหล็ก กดปุ่ม → ตรวจ | ข้อความ "ต้องมีเหล็กอย่างน้อย 2 ชิ้น" |
| 2 | คาน 2 ตัวที่เหล็กยืนของตัวหนึ่งทะลุเข้าเหล็กอีกตัว เลือกคานทั้งสอง → ตรวจ | พบ 1 กลุ่มคู่ host สถานะ ชน gap ≤ 0 |
| 3 | คานเหล็กอยู่ห่างกัน 10 มม. (ผิวต่อผิว) clearance 0 | ไม่รายงาน; ตั้ง clearance 25 → รายงาน "ใกล้เกิน" gap ≈ 10 |
| 4 | คลิกแถวคู่เหล็ก | ใน view เลือกเหล็กสองเส้นและซูมไปที่ตำแหน่ง; คลิกแถวกลุ่ม = เลือกเหล็กของกลุ่ม (สูงสุด 300 คู่) |
| 5 | ตั้งจำนวนคู่สูงสุด = 1 บนโมเดลที่มีหลายคู่ | สรุปบอก "ยังไม่ได้ตรวจละเอียด N คู่" |
| 6 | กด "ยกเลิกการตรวจ" ระหว่างโมเดลใหญ่ | หยุด แสดงผลที่ได้ถึงตอนนั้น + "ยกเลิกกลางคัน" |
| 7 | ไม่ติ๊ก "ตรวจละเอียด" | ทุกคู่ที่ bbox ซ้อนขึ้นเป็น "bbox ซ้อน (ยังไม่ยืนยัน)" |
| 8 | ส่งออก CSV แล้วเปิดใน Excel | ภาษาไทยไม่เพี้ยน มีคอลัมน์ host A/B, เหล็ก A/B, id, สถานะ, gap, จำนวนจุด, X/Y/Z (มม.) |
| 9 | พื้นที่ใช้ Area Reinforcement ชนกับเหล็กคาน | พบเป็น solid-based (ไม่ขึ้น gap) หรือ "ยังไม่ยืนยัน" |

### กรณีขอบ / ข้อจำกัด
- เส้นศูนย์กลางของเหล็กโค้งใช้ polyline จาก Tessellate (ประมาณ) — gap คลาดเคลื่อนเล็กน้อยที่ส่วนโค้ง
- ชุดเหล็กจำนวนตำแหน่งมาก (เช่น 200+) ช้าลง — มี bbox กรองรายตำแหน่ง
- host ที่มีเหล็กน้อยกว่า 2 ชิ้นในขอบเขต ไม่มีอะไรให้เทียบ
- **ต้องยืนยันใน Revit**: `GetCenterlineCurves` กับ barPositionIndex, `BarModelDiameter`, geometry ของ FabricSheet/RebarInSystem

## B. Color by Parameter
### ทำอะไร
1. โหมดเหล็ก: Partition, Bar Type, Shape, Mark, Comments (Rebar/RebarInSystem/FabricSheet) · โหมดโครงสร้าง (ติ๊กหมวด คาน/เสา/ฐานราก/พื้น/ผนัง): Mark, Type Mark, Family, Type Name, Comments (พื้น/ผนังใช้ชื่อ family ของ type)
2. "สแกนค่า" → ค่าที่ไม่ซ้ำเรียงแบบ natural (B2 ก่อน B10) พร้อมจำนวน element; สีอัตโนมัติ ไล่เฉด (ส้ม→เขียว) หรือคอนทราสต์สูง; "สุ่มสีใหม่"; คลิกช่องสี = เลือกสีเอง (ColorDialog); กรองค่าด้วยช่องค้นหา; ติ๊กเลือกค่า
3. ระบายด้วย `OverrideGraphicSettings` ต่อ element (`View.SetElementOverrides`) — ไม่ใช้ ParameterFilterElement; ตัวเลือก ทึบ (fill+เส้น) หรือเส้นขอบอย่างเดียว; Transaction เดียว
4. ใช้กับ **view ปัจจุบัน** หรือ **หลาย view** ที่เลือก (สีของค่าเดียวกันเหมือนกันทุก view)
5. จำสีล่าสุดต่อ (โหมด, พารามิเตอร์) ใน `%LOCALAPPDATA%\PKRevit\ColorByParameter.json` — สแกนครั้งหน้าค่าเดิมได้สีเดิม
6. จำ id element ที่ระบายไว้ต่อ (โปรเจกต์, view) + สีที่ใส่ — **Reset** รีเซ็ตเฉพาะ element เหล่านั้น และข้าม element ที่สีถูกเปลี่ยนไปจากที่เราใส่ (นับให้ในสรุป); มีปุ่ม Reset view ปัจจุบัน / ทุก view ที่เคยระบาย; ระบายใหม่จะล้างสีเก่าของเครื่องมือใน view นั้นก่อน
7. เลือก element ไว้ก่อนกดปุ่ม = สแกน/ระบายเฉพาะที่เลือก

### ขั้นทดสอบและผลที่คาดหวัง
| # | ทำ | คาดหวัง |
|---|---|---|
| 1 | โหมดเหล็ก พารามิเตอร์ Bar Type สแกน | พบค่า DB12/DB16/RB9... แต่ละค่าสีต่างกัน จำนวนตรงกับของจริง |
| 2 | ระบาย ทึบ | เหล็กใน view เปลี่ยนสีตามค่า (เห็นชัดใน 3D/shaded) |
| 3 | เปลี่ยนสีค่าหนึ่งด้วยช่องสี → ระบาย | element ค่านั้นใช้สีใหม่ |
| 4 | ปิดแล้วเปิดใหม่ สแกนพารามิเตอร์เดิม | ค่าเดิมได้สีที่เลือกไว้รอบก่อน |
| 5 | โครงสร้าง: Family / Type Name กับคาน+เสา+พื้น | ระบายได้ ไม่ error (ต่างจาก filter ของ PK Tool) |
| 6 | เลือกหลาย view → ระบาย | ทุก view ที่เลือกมีสีเดียวกัน |
| 7 | ผู้ใช้ตั้งสี override ของ element ตัวหนึ่งเอง (ใน VG) แล้วกด Reset | ตัวนั้นไม่ถูกรีเซ็ต สรุปบอก "ข้าม 1"; element อื่นที่เราระบายถูกรีเซ็ต |
| 8 | element ที่มี override ของคนอื่นแต่เราไม่ได้ระบาย กด Reset | ไม่ถูกแตะ |
| 9 | Ctrl+Z หลังระบาย / Reset | ย้อนทั้งชุด |
| 10 | view ที่ถูกล็อกด้วย template | บอกจำนวนที่ระบายไม่สำเร็จ ไม่ล้มทั้งงาน |

### ข้อจำกัด
- สีเป็น snapshot — element ที่เพิ่มทีหลังไม่ถูกระบายเอง ต้องสแกน/ระบายซ้ำ
- ถ้า element มี override ของคนอื่นอยู่ก่อนแล้ว การระบายจะทับ และ Reset จะล้างเป็นค่าว่าง (ไม่ได้คืนค่า override เดิม)
- แถบ Preset กลาง (`RevoWindow`) จับค่าช่องในฟอร์มทั้งสองนี้ได้ แต่ไม่เก็บผลสแกน/สี — ต้องสแกนใหม่หลังโหลด
- **ต้องยืนยันใน Revit**: การอ่าน `ProjectionLineColor` เพื่อเทียบก่อน Reset, ผลของ solid fill บนเหล็ก, การเรียก `SelectFromList` ซ้อนในฟอร์ม
