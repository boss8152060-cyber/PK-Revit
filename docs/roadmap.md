# Roadmap: ทำฟีเจอร์ให้ครบตามคลิป

อ้างอิงรายการฟีเจอร์ใน [features.md](features.md) และช่องว่างใน [gap-analysis.md](gap-analysis.md)
เวอร์ชัน: `PK-Revit 0.X.0` ต่อหนึ่งโมดูลที่เสร็จ (ดูรูปแบบ commit ใน CLAUDE.md)

## หลักการ
- ทุกโมดูลเป็นปุ่มบนแท็บ REVOTECH ในส่วนขยายเดียว (`RoofMaster/REVOTECH.extension` จะเปลี่ยนชื่อโฟลเดอร์เป็น `PK-Revit.extension` ตอนจัดโครงใหม่)
- ใช้ธีมฟอร์มเดียวกับ Roof Master (WPF ขาว-ดำ (PK)) และ popup สรุปผลแบบเดียวกัน
- ทุกโมดูลห่อ `TransactionGroup` เดียว Ctrl+Z ครั้งเดียวย้อนได้
- โค้ดเขียนสำหรับ IronPython 2.7 บน Revit 2026 (ตามที่ v2 ใช้) ยืนยันกับ pyRevit ที่ติดตั้งก่อนเริ่มโมดูลใหม่
- โมดูลใหม่ทุกตัวต้องมีไฟล์เกณฑ์ตรวจรับ `docs/accept-<module>.md` (input, ผลที่คาดใน Revit, กรณีขอบ)

## ข้อจำกัดด้านการตรวจสอบ
ผมไม่มี Revit ที่ทดสอบเองได้อย่างเสถียร (การคลิกเมาส์ใน Revit ผ่านเครื่องมือของผมไม่ติด และเคยเปิด Revit ซ้ำโดยไม่ตั้งใจ) ดังนั้นโค้ดทุกโมดูล "ตรวจ syntax + อ่านทบทวน" ได้เท่านั้น ความถูกต้องของเรขาคณิตและผลใน Revit ต้องให้ผู้ใช้รันและส่งผลกลับ ค่าวิศวกรรมต้องยืนยันจากผู้ใช้

## คำถามที่ต้องการคำตอบจากผู้ใช้ (ก่อนเขียนโมดูลที่เกี่ยวข้อง)
1. ค่ามาตรฐานเหล็กที่ใช้ (มยผ. 1103-64 เป็นค่าตั้งต้น?), ระยะทาบ, ขนาดตะขอ
2. ขั้น 0 ใน Roof Master คืออะไร (ใน features.md ระบุ "ไม่แน่ใจ")
3. ตัวอย่างโปรเจกต์ Revit สำหรับทดสอบแต่ละโมดูล (ฐานราก/เสา/คาน/พื้น/บันไดที่มีอยู่แล้ว)
4. ต้องการ license และ 3 ภาษาตั้งแต่ต้นหรือท้ายสุด
