# เกณฑ์ตรวจรับ: Rebar Shape / ตะขอ / ระยะต่อทาบ ในฟอร์มเหล็ก (เสา คาน ฐานราก)

**สถานะ: เขียนโค้ดแล้ว ยังไม่เคยรันใน Revit** — ตรวจได้แค่ syntax, unit test (`python tools/run_all_tests.py`) และ render ฟอร์มด้วย WPF
(`tools/preview_demo/demo_forms.py` → `form_column_hooks.png`, `form_beam_hooks.png`, `form_footing_shapes.png`)

## ตัวเลือกใหม่ (ท้ายฟอร์ม ก่อน "ด่านตรวจก่อนสร้าง")
| ช่อง (x:Name) | เสา | คาน | ฐานราก | ความหมาย |
|---|---|---|---|---|
| `cmb_shape_main` | ✓ | ✓ | ✓ | Rebar Shape เหล็กหลัก (RebarStyle.Standard) จากโปรเจกต์จริง ชื่ออะไรก็ได้ ไม่เดาจากชื่อ |
| `cmb_shape_tie` | ✓ | ✓ | ✓ (ใช้กับเหล็กรัดรอบเฉพาะฐานสี่เหลี่ยม) | Rebar Shape ปลอก (RebarStyle.StirrupTie) |
| `cmb_hk_a/b`, `tb_hk_a/b` | ✓ | ✓ | – | ตะขอปลายซ้าย(ล่าง)/ขวา(บน): ค่าเดิมของโมดูล / ไม่มี / 45° / 90° / 135° / 180° + ตัวคูณ × d (ว่าง = ค่ามาตรฐานของมุม) |
| `cmb_stagger` | ✓ | – | – | สลับจุดต่อเส้นเว้นเส้น |
ค่าตั้งต้นทุกช่อง = **ค่าเดิม / อัตโนมัติ** → ถ้าผู้ใช้ไม่แตะ ผลสร้างเหมือนเดิมทุกประการ (พฤติกรรมเดิม: เสา = เส้นตรงไม่มีตะขอ ปลอก 135°; คาน = ขา 90° 12d ที่ปลายคาน; ฐานราก = ตัวเลือกตะขอเดิม)
ตัวเลือกใหม่ทั้งหมดเป็น control ที่มี x:Name จึงเข้า Preset และ `hostconfig` (Propagate) อัตโนมัติ; ค่าเก่าที่ไม่มีคีย์ = ค่าเดิม; ชื่อ shape ที่ไม่มีในโปรเจกต์ปลายทาง → ใช้อัตโนมัติและเขียนใน log

## วิธีสร้าง
- **อัตโนมัติ**: `Rebar.CreateFromCurves` เหมือนเดิม; ตะขอที่เลือกใช้ `RebarHookType` ที่มีชื่อ `PKRevit_Hook<มุม>_<ตัวคูณ>d` หรือตัวที่มุม+ตัวคูณตรง ไม่มีก็ `RebarHookType.Create` (rebar.py `hook_type_for`)
- **เลือก Shape**: `Rebar.CreateFromRebarShape(doc, shape, barType, host, origin, xVec, yVec)` แล้ว `ScaleToBox` แบบ PK Tool (`Core/ColumnRebarCreator.cs`, `RebarCreator.cs`) — ปลอก: origin = มุมกล่อง xVec/yVec = ด้านกว้าง/ลึก แล้วเรียงด้วย layout เดิม; เหล็กหลัก: xVec = ความยาวท่อน, yVec = ขา (ทิศเข้าหาแกน/ทิศตะขอเดิม) ยาว `max(4d, 0.15 L)` (สูตรเดียวกับ PK Tool) **ตะขอมาจากตัว shape — ตัวเลือกตะขอปลายซ้าย/ขวาถูกข้าม** (บันทึกใน log)

| ระยะทาบ 40d | `rebar.LAP_D` | – |
| ระยะเหลื่อมจุดต่อเมื่อสลับ = 1.3 × ทาบ | | `STAGGER_FACTOR` |

## ความยาวตัด / BarCut
- `hookcalc.py` (ทดสอบแล้ว `test_hookcalc.py`): ความยาวตะขอ = ส่วนโค้งตามแกนกลาง + ช่วงตรงปลาย; `cut_length_mm`, `spliced_cut_length_mm` รวมตะขอ/ทาบ เป็น **ค่าประมาณ** สำหรับ preview/วางแผน
- **BarCut ไม่ได้คำนวณเอง** — `ผลลัพธ์.panel/BarCut.pushbutton/script.py` อ่านจาก `Rebar.GetCenterlineCurves(adjustForSelfIntersection=False, suppressHooks=False, suppressBendRadius=True, ...)` ของ Revit จึงรวมตะขอที่สร้างอยู่แล้วโดยไม่ต้องแก้ แต่ใช้ `suppressBendRadius=True` → ความยาวต่างจากค่า Revit ที่รวมโค้งเล็กน้อย (ข้อจำกัดเดิม ไม่ได้แก้ในงานนี้)

## ต่อทาบ
- ช่อง "ต่อทาบ × d" เดิมคงอยู่: เสา = ปลายบนยื่นเหนือเสา (+ สลับ: เส้นคี่ยื่นเพิ่ม 1.3×ทาบ); คาน = ตัดท่อนเมื่อยาวเกิน และเลื่อนจุดต่อบน/ล่างไม่ให้ซ้ำ (beamcalc เดิม) จึงไม่เพิ่มตัวเลือกสลับในคาน
- **การค้น API (ผลค้นเว็บ ไม่ได้ทดลอง)**: `RebarCoupler.Create(doc, typeId, ReinforcementData, ReinforcementData, out error)` สร้าง *ข้อต่อกล* (coupler) ระหว่างเหล็ก 2 เส้น ไม่ใช่การต่อทาบ; มี `RebarSpliceTypeUtils` สำหรับกำหนดชนิด splice (ความยาวทาบ/stagger) แต่ผลค้นไม่พบเมธอดที่ "สร้างจุดต่อทาบ" ระหว่างเหล็กสองเส้นให้ → **ยังไม่มีวิธีที่ยืนยันได้**; ใช้การต่อเส้นเองเหมือนเดิม; ยังไม่ได้ทำ Coupler (เพิ่มได้ถ้าต้องการต่อกล)
  ที่มา: [RebarCoupler.Create](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/52fc10f6-e5b0-0f47-20fa-90be57b48004.htm), [RebarSpliceTypeUtils](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/98b9e51e-cd97-954d-4a31-a5189696b27e.htm)

## 3D preview
เสา: แสดงตะขอปลายล่าง/บนและการสลับความสูงจุดต่อ; คาน: แสดงตะขอตามมุม/ตัวคูณที่เลือก (หรือไม่แสดงเมื่อเลือก "ไม่มี"); ฐานราก: ไม่เปลี่ยน
**เป็นภาพประมาณ** — ตะขอวาดเป็นเส้นตรงตัดมุม (ไม่มีส่วนโค้ง) ทิศเบนเข้าหาแกนเสา/ทิศตะขอเดิมของคาน; เลือก Rebar Shape แล้ว preview ยังแสดงแบบอัตโนมัติ

## ขั้นทดสอบใน Revit
| # | ทำ | คาดหวัง |
|---|---|---|
| 1 | เปิดฟอร์มเสา/คาน/ฐานราก ไม่แตะช่องใหม่ สร้าง | ผลเหมือนก่อนเพิ่มช่อง |
| 2 | dropdown Rebar Shape | แสดงรายการ shape จริงของโปรเจกต์ แยกหลัก/ปลอก |
| 3 | เสา: ตะขอล่าง 90° บน 135° ตัวคูณว่าง | มี RebarHookType `PKRevit_Hook90_12d` / `PKRevit_Hook135_...`; ตะขอหันเข้าในเสา **(ทิศนี้ยังไม่ยืนยัน — ถ้าหันออกให้แจ้ง)** |
| 4 | เสา: สลับจุดต่อ | เส้นคี่ยื่นสูงกว่าเส้นคู่ 1.3×ทาบ |
| 5 | คาน: ปลายซ้าย 45°, ปลายขวา ไม่มี | ปลายซ้ายงอ 45° ปลายขวาตรง; ตะขอที่รอยต่อท่อนไม่มี |
| 6 | เลือก Shape เหล็กหลัก (เช่น ตัว L) / ปลอก | สร้างจาก shape ขนาดพอดีหน้าตัด; ถ้าขา L หันผิดทิศหรือขนาดผิด ให้แจ้ง (สูตร yVec ยังไม่ยืนยัน) |
| 7 | ฐานราก: Shape ปลอกกับฐานสามเหลี่ยม | ใช้แบบอัตโนมัติ (shape ปลอกรองรับเฉพาะฐานสี่เหลี่ยม) |
| 8 | บันทึก Preset / Propagate | ค่าช่องใหม่ถูกจำและใช้ซ้ำ |
| 9 | Ctrl+Z | ย้อนทั้งชุด รวม Hook Type ที่สร้างใหม่ |

## ยังไม่ทำ / ข้อจำกัด
- พื้นและบันได: ยังไม่เพิ่ม (พื้นใช้ชุดเหล็ก 2 ทิศหลายชั้น ต้องออกแบบแยก)
- ฐานราก: ไม่มีตัวเลือกตะขอ 45/135/180 (ใช้ตัวเลือกขา 90°/เต็ม/ไม่มีเดิม); เหล็กตะแกรงที่เลือก Shape ใช้ขาชี้ขึ้น
- ตะขอที่ปลายซ้าย/ขวาของเสาเมื่อเลือกตะขอในโหมดอัตโนมัติใช้ orientation `Left` + ทิศเข้าหาแกนที่คำนวณเอง
- `RebarHookType.Multiplier` ใช้ตามที่โมดูลคานเดิมใช้ (ยังไม่ยืนยันว่ามีใน API 2026) — ถ้าไม่มี จะสร้าง hook type ใหม่ทุกครั้งที่ชื่อไม่ตรง
